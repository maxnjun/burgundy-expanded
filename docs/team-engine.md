# 데이터 주입형 기본 팀 엔진

**팀 UI/공식 팀 보드 선택은 아직 없다.** 엔진·저장 함수와 TEST FIXTURE의25라운드 검증을 팀전 제품 전체 완료로 보고하지 않는다. 공식 PDF p.15 기본 규칙과 기존 기본판 효과 해석기를 재사용했다. 추가 확장 조합은 지원하지 않는다.

## 상태·행동

- team-types/state: TeamGameState에 팀당 영지·일꾼·은화·상품·판매 상품·색 보너스를 한 번만 보관한다. 개인은 주사위2개·개인 보관2칸·득점 원장을 가진다. 공유 보관은 팀당2칸이다.
- createTeamGame: 플레이어 순서 A1,A2,B1,B2와 검수할 보드2개·시작 성/타일·팀당 상품3개·타일/공급·난수를 주입한다. A 일꾼3/B 일꾼5, 은화2씩, 초기 턴은 A1,B1,A2,B2다. 공식 보드를 자동 생성하지 않는다.
- applyTeamAction/validateTeamAction/listTeamActions: 기존 GameAction을 사용한다. 보관 인덱스0/1은 자신의 개인 칸,2/3은 팀 공용 칸이다. 다른 팀원의 개인 칸이나 주사위는 사용할 수 없고 보관 간 이동 명령은 없다. 네 칸이 모두 찼을 때만 정확한 점유 타일을 명시해 폐기/교체한다.
- 기본 획득·일꾼·판매·구매·배치·성/건물/선박·수도원 효과를 연결했다. 개인 행동으로 획득한 점수는 행동한 개인 원장에 기록하고 자원 변화는 공유 팀에 한 번 반영한다. 부분 단계 건너뛰기, 미해결 선택을 둔 턴 종료, 위조/재사용 선택은 거절한다.
- 선박은 개인 표식을 이동한다. 마지막6칸에서는7칸을 만들지 않고 스택 위로 이동한다. 수도원5의 두 상품 창이 끝난 뒤 한 번 이동한다.

기존 기본판의3칸 제약은 validateCoreState에서 그대로 유지한다. 하위 보관·즉시효과 생성기만 실제 입력 보관 길이를 사용하도록 일반화했다. 팀 전이에는 기존 기본판 상태 검증을 무력화하는 예외를 넣지 않았다.

## 내부 규칙 보기의 경계

team-rule-view.ts는 검증된 TeamGameState를 기존 하위 규칙 함수의 입력 형태로 잠시 투영한다. 이때 두 팀원이 같은 영지/자원을 보지만 **이 보기는 canonical GameState가 아니다**. core의 상태 검증·저장·온라인 응답에 사용하지 않는다. 실제 복원은 행동한 개인의 보관/원장과 단일 팀 영지/자원만 갱신한다. canonical 팀 상태 검증은 모든 타일이 물리적으로 딱 한 위치에 있는지 확인한다. 테스트에서 투영 보기를 기존 validateCoreState가 거절하는 것도 확인한다.

## 단계·종료

advance-phase는 단계 종료 후 트랙 선두만 실행한다. 광산 수입·수도원2 일꾼은 팀당 한 번 지급한다. 다음 단계 공급을 사전 확인하고, 부족하면 수입/난수까지 원자적으로 보존한다. 상품은 공급처에 유지하고 남은 육각 타일만 폐기한다. supply.ts의 비복원 추첨은 기본판과 공유한다.

marketRecipeId를 se:main:3-4로 주입하면 검수된4인24+8칸 배치를 검사한다. 미지정 시 주입한 연습 슬롯을 유지한다. 슬롯 검증은 공식164개 재고의 전수 검증과 별개다.

E단계 수입 후 개인 기득점 둘의 합과 공유 잔여 자원/수도원 종료 점수를 합산한다. 공유 종료 점수는 한 번만 산출하며 특정 팀원에게 임의로 배분하지 않고 TeamFinalScore.sharedAdditions에 기록한다. 동점은 **빈칸이 더 많은 팀**이 앞선다. 그것까지 같으면 tied로 남기며 추가 공식 동점 규칙을 만들지 않는다. 종료 조회는 순수 함수이며 종료/수입 재적용을 거절한다.

## 저장

team-save.ts의 별도 형식 burgundy-team-save-v1/counter-v1을 사용한다. 기존 burgundy-local-v1은 변경하지 않는다. 신뢰할 보드/타일 카탈로그를 호출자가 별도로 전달하며 저장 파일 자체의 카탈로그를 신뢰 근거로 사용하면 안 된다. 크기·깊이·노드 수·프로토타입 키, 실제 상태/형상/타일 정의/다음 단계 상품을 검사한다. 선택 대기 중과 종료 상태의 복원도 검사했다. 오프라인 저장의 구조 검증이지 행동 이력의 암호학적 인증이 아니다. 현재 브라우저 자동 저장/온라인 방은 이 형식에 연결되지 않았다.
