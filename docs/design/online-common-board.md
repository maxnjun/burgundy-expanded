# 온라인 공용 게임판 통합 (2026-10-24)

## 원인과 기준

온라인 `room-screen.tsx`는 로컬 `CommonBoard`를 사용하지 않고 방패 목록 → 플레이어별 무역로 → 공급처 flex 목록 → 포도 공급처 순서로 별도 렌더링했다. 데이터 동기화는 되어도 게임판의 공간 관계가 없어지는 원인이었다. 기존 공용 보드 SVG를 재사용하며 엔진·추첨·수량·영지 좌표·저장 형식은 변경하지 않는다.

확인한 프로젝트 자료:
- `reference/official-rulebook-public.pdf`에서 추출한 `reference/pdf-p2-image-9.png`: 6개 번호 공급처가 중앙 검은 공급처를 둘러싸는 기본 구조. 원본 자료는 Git 제외 상태로 보존한다.
- [검증된 최종 공용 보드 좌표](common-board-layout.md): 사용자 최종 승인 좌표, 1번 위/4번 아래, 네 모서리 정보 패널, 방패 전용 회색 공간.
- [방패 조사·구현 기록](../shield-ui.md): 공식 PDF p.17의 2/3/4인 방패 6/9/12개 및 각 번호 공급처와의 대응.
- [포도밭 조사](../research/vineyards-reconstruction.md): 공식 규칙서 p.19의 별도 공급대·상점·공용 보너스 토큰. 화면 오른쪽에 붙이는 것은 UI 설계이며 공식 지정 픽셀 위치라고 주장하지 않는다. 프로젝트 복원판 v0.2 데이터는 그대로다.
- [커스텀 무역로 확정 규칙](../rules/custom-trade-routes.md): 플레이어별 배분·진행 상태이므로 각 개인 영지 아래에 표시한다. 공식 카드 데이터로 대체하거나 규칙을 재해석하지 않는다.

## 배치

기본 SVG **950×1030**, 중심 **(475,540)** 및 기존 타일 폭60을 유지한다. 상세 타일·방패·상품 좌표는 기존 공통 설계 한 곳에서 관리한다.

| 영역 | 위치 |
|---|---|
|1/4번 상품 중심|(475,390)/(475,690)|
|2/3번 상품 중심|(650,390)/(650,690)|
|5/6번 상품 중심|(300,690)/(300,390)|
|1/4번 방패 그룹|(475,160)/(475,920)|
|2/3번 방패 그룹|(900,390)/(900,690)|
|5/6번 방패 그룹|(50,690)/(50,390)|
|검은 공급처/여관|(475,540)/(325,540)|
|상단 패널|좌(18,18), 우(542,18), 각390×205|
|하단 패널|좌(18,857), 우(542,857), 각390×155|
|포도 공급대·상점·토큰|기본 게임판 오른쪽, 간격12 CSS px, 패널 폭300px|
|무역로|각 영지 아래, 현재 카드 기본 표시, 전체 펼침 시 가로 스크롤|

PC에서는 기본 보드를 가용 너비에 맞춰 표시하고 오른쪽 레일은 콘텐츠에 맞춘 높이로 유지한다. 모바일에서는 기본 보드 최소640px/포도 레일300px과 상대 위치를 유지하며 바깥 컨테이너를 가로 스크롤한다. 보드 자체의 기존 드래그·확대(75~200%, Ctrl+휠/이동 모드 두 손가락 포함)는 재사용한다. 모바일용 세로 재배열이나 잘라내기 처리는 하지 않는다. 기존 로컬 화면의 고정 크기·배치는 바꾸지 않는다.

## 입력과 데이터 보호

- 타일·상품·방패는 같은 SVG 내부 좌표로 그리며 기존 `pickTile`, `GoodsSpace`, 서버 `BoardTarget` 합법 행동을 그대로 연결한다. 방패 선택 후 실제 영지의 성을 선택하는 흐름과 필수 교체 확인은 유지한다.
- 서버 `RoomView.commonBoard`에 순서 트랙·단계별 상품 수량·남은 라운드 상품 개수·색상 완성 보너스만 추가한다. 아직 공개되지 않은 라운드 상품의 종류는 보내지 않고 뒷면을 그린다. RNG/덱/토큰/Undo 이력은 여전히 서버 전용이다.
- 저장 방 JSON에는 새 필드를 쓰지 않는다. 오래된 방도 기존 상태에서 표시 데이터를 계산하며, Undo·시작 성 임시 배치·동기화 프로토콜을 바꾸지 않는다.

## 검증/증거

`tests/browser/online-board.spec.ts`: 확장 전체 활성화·격리된 실제 서버/두 좌석으로 6공급처/방패/네패널/중앙시장, 무역로 소속, 모바일 좌우 관계, 100/160/200% 겹침 및 모든 방패·타일·상품 hit 검사, 실제 획득/검은구매/Undo/포도획득/상대동기화/새로고침을 확인한다. 기존 온라인 방패/여관/선박·상품/무역로/Undo·시작 성 테스트는 새 실제 요소 선택자로 연결하며 상태·보상 검증을 유지한다. PC와 Chrome터치/WebKit CI에도 포함한다.

로컬 비공개 증거 경로: `.local-data/online-board/`의 before/after/pc-regression 및 테스트 로그. 최종 통과 수와 남은 범위는 최신 PROGRESS를 따른다. 실제 Render 배포·운영 방 접근·유료 리소스 생성은 하지 않는다.
