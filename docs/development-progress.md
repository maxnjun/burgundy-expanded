## 4. 필요한 공식 자료와 중단 사유

1. **기본 영지 1~10 각 면의 선명한 정면 스캔/사진 또는 출판사 PDF.** 면 번호, 전체 테두리, 모든 색과 주사위 눈이 보이고 타일이 가리지 않아야 한다. 최소 한 면으로 같은 보드를 쓰는 제한된 시작은 가능하지만, 서로 다른 보드 선택에는 여러 면이 필요하다. 규칙서 구성품 사진에는 겹치거나 보이지 않는 면이 있다.
2. **공용 보드 양면(2인/3~4인)의 전체 도면.** 공급처 1~6의 색상·4인 표시·3BD 표시·검은 공급처 슬롯이 읽혀야 한다. p.4 그림에는 설명 원이 일부를 가리고 2인 면은 없다. 색상 슬롯이나 검은 공급처 수를 임의로 채우지 않는다.
3. **기본 타일 전수 구성 자료.** 가축 종류·동물 수·뒷면, 수도원 1~26의 번호·뒷면, 건물 종류와 뒷면별 수량을 확인할 수 있는 구성표나 사진. 수도원 16~23의 건물 도상 대응은 선명한 도움말/타일 자료로 교차 검토한다.

구역 점수표를 위해 추가 자료를 요청할 필요는 없다(U04 해소). 기본판 범위에 없는 영지 11~36과 확장 자료는 이번 재개 필수 조건에 넣지 않는다. 미확정 항목은 rules/unresolved.md의 U01~U03, U05~U12를 유지한다.

## 5. 최신 UI 요청과 기존 명세의 차이

- 사용자의 최신 요청은 내 보드 중심 모드의 상단 영지를 **현재 플레이어**로 지정했다. 기존 명세의 고정 '내 플레이어' 규정보다 최신 요청을 우선 적용할 계획이다.
- 사용자가 Ctrl+휠의 보드 확대를 허용했다. 후속 구현에서는 보드 위 Ctrl+휠을 처리하고 일반 휠의 페이지 스크롤을 유지한다. 기존 Alt+휠·브라우저 Ctrl 확대 보존 규정과 다른 점을 구현 시 명세에 반영한다.
- 반응형 기본 열 접기는 유지하며, 기존 명세의 별도 자동 최적화 토글과 구분한다. 보기 조작은 GameAction이나 점수 변경을 발생시키지 않는다.
- 현재 Phase 1에서는 UI나 기존 명세를 변경하지 않았다.

## 6. 자료 확보 후 구현 순서와 완료 기준

### Phase 2: 엔진

1. 공식 자료 전수 입력 → 보드 구조 검사와 별도 원문 대조 → 검증 카탈로그 등록. 초기에는 검증된 기본판 면만 허용.
2. 설정·카탈로그 런타임 검증, 재현 가능한 seed 난수와 셔플, createGame 초기화. 불완전 카탈로그는 명시적으로 거절.
3. 공통 GameAction 검증, 소유권·차례·주사위 사용·자원·보관 검사, 실패 시 입력 상태 불변, 성공 시 revision과 이벤트 기록.
4. 일꾼/주사위 → 타일 획득 → 판매/일꾼 획득/검은 공급처 → 배치 → 단순 타일 효과 → 선택·성·시청 연쇄 → 수도원 예외 순서로 구현.
5. 구역·색상 득점과 광산 수입, 동적 순서 트랙과 이미 행동한 플레이어 처리, 라운드·단계·종료·승자 판정.
6. 함수별 단위 테스트와 전이 불변식이 통과한 뒤 UI 연결. 단계가 끝날 때까지 통과하지 못한 항목을 완료로 표시하지 않음.

### Phase 3: 화면 연결

현재 SVG/CSS 디자인과 엔진을 읽는 어댑터를 분리한다. 공용 보드와 2~4인 영지 동시 렌더, 전체/현재 플레이어 중심 모드, 50~200% 전체·개별 배율, 맞춤·초기화·드래그를 구현한다. 선택·보기 상태는 게임 상태와 별도로 유지한다.

### Phase 4: 저장과 검증

직렬화 버전, 저장값 런타임 검증, 새로고침 복원, 잘못된 저장·저장소 차단 처리, 새 게임 초기화를 구현한다. 보기 설정과 게임 저장을 분리하고, 실제 기본판 UI가 연결된 뒤 브라우저 회귀를 수행한다.

### Phase 5: 완성 판정

2/3/4인 각각 새 게임부터 E 종료까지 진행한다. 25라운드, 효과 연쇄·색상 선점·최종 득점·승자, 저장/복원 후 재현성을 확인한다. 성공한 검증 카탈로그·인원·모드와 남은 미구현을 명시한다. 합성 fixture나 v0.1 데모를 공식 기본판 완성 증거로 사용하지 않는다.
