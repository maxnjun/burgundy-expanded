# 영지 완성 보상 타일 — 로컬 검증

## 범위와 보존

- 승인 원본 5파일에서 6종을 분리했다. `asset-inbox/estate-bonus-approved/originals/`와 manifest에 원본/해시를 보존한다. 성 파일은 첨부 clipboard와 동일한 원본을 사용했다.
- 도시·수도원은 합본의 왼쪽/오른쪽이다. 내부 그림을 **균일 배율**로 맞추고 광산 원본의 초록·갈색·금색 프레임을 사용했다. 전체 이미지를 가로/세로로 따로 늘리지 않는다.
- 기존 SVG 임시 보상 에셋도 보존했다. 원본 타일, 다른 이미지, 게임 엔진, 서버, 저장 형식, 운영 방·Redis·환경변수는 수정하지 않았다.
- 구현·검증 당시 로컬만 진행했다. 후속 사용자 승인으로 이번 관련 변경만 **GitHub main Commit/Push**하며, **Render 배포·재시작은 계속 금지**한다. 기존 문서 dirty 본문과 수도원27·28 PNG는 보존·백업 제외한다.

## 공통 이미지와 숫자

- 게임용 `public/assets/tokens/estate/{color}-{points}.png`: 1024×1024 RGBA, 6종 × 2·3·4·5·6·7점 = **36장**.
- 동일 광산 실루엣 마스크를 사용한다. 원본 좌표 경계 `(70,147,1183,1066)`를 960×793으로 균일 축소하고 캔버스 중앙에 배치했다. 모든 결과의 알파 채널이 완전히 같다.
- 일반 시스템 글꼴을 사용하지 않았다. 광산의 아이보리 질감 5를 공통 참조로 추출하고 가장자리를 정리했다. 같은 재질·형태 계열로 만든 2/3/4/6/7도 점수별 **하나의 공통 숫자 PNG**를 사용한다.
- 공통 숫자 레이어: `public/assets/tokens/estate/numerals/{2,3,4,5,6,7}.png`. 같은 숫자의 본체/테두리/그림자/질감은 6종에서 모두 같다. 작은 알파 찌꺼기는 가장 큰 연결 성분만 남겨 제거한다.
- 금색 내부 그림 영역 마스크의 면적 중심을 같은 변환으로 계산한 기준은 **(513,509)**다. 5의 실제 본체 경계는 **(403,359)–(623,659)**, 크기 **220×300**, 중심 **(513,509)**다.
- 2의 실제 본체 경계는 **(396,359)–(631,659)**, 크기 **235×300**, 중심 **(513.5,509)**다. 홀수 픽셀 너비 반올림에 따른 0.5px 차이이며, 6종 사이의 숫자 윤곽/좌표 차이는 0이다. 글자를 찌그러뜨려 반 픽셀을 감추지 않는다.
- 원본 숫자 뒤의 실제 그림 픽셀은 원본에 존재하지 않는다. imagegen으로 숫자 제거용 중앙 배경을 보완한 뒤, 중앙 `(355,370)–(645,724)` 및 페더 범위만 원본에 합성했다. 테두리와 그 밖의 그림은 원본 픽셀을 유지한다. 사용한 참조/프롬프트/중간물은 입력 폴더의 `EDIT_NOTES.md` 참조.
- `prepare-estate-bonus-assets.py --check`는 입력 해시, 출력36장 재현, 전체 알파 일치, 불투명 숫자 픽셀 일치, 중심과 프레임 보존을 검사한다. 배경이 다른 가장자리 반투명 픽셀은 안티앨리어싱 합성 차이로 구분한다.

## 게임 연결과 최종 문구 정리

- `EstateBonusArt`가 기존 `BonusTile.color/points/rank`를 읽어 manifest의 실제 PNG에 연결한다. 파일 해시 쿼리로 캐시를 갱신한다. 알 수 없는 과거 점수는 다른 숫자 이미지를 꾸며 쓰지 않고 실제 점수의 텍스트로만 대체한다.
- 공용 보드 오른쪽 아래의 기존 390×155 패널 안에 **3열 × 2행**을 유지한다. 중심 x=65/195/325, y=38.75/116.25(패널 내부 좌표)다. 1위 SVG66px, 2위49.5px로 **정확히75%**, 같은 중심에서 2위부터 그리고 1위를 위에 그린다.
- 추가 요청대로 공용 보상의 제목/종류 이름/소진 문구는 모두 제거했다. 남은 보상 **이미지만** 표시한다. 접근성 이름과 이미지의 실제 숫자는 유지한다. 보상 둘 다 없으면 그 자리도 빈 상태다.
- 개인 보드 상단 오른쪽 기존 `EarnedBonusTiles`를 사용한다. 실제 획득분만 표시하며 이미지 크기는 1위60px, 2위45px다. 이미지 옆 `5점`/`2점` 문구와 해당 간격을 제거했다. 온라인과 로컬이 같은 컴포넌트를 쓴다.
- 다른 공용 보드 좌표와 SVG viewBox 950×1030은 그대로다.

## 기존 규칙 재사용

새 지급 엔진을 만들지 않았다. `core/placement.ts`의 기존 색상 전체 완성 판정으로 시장 보상 하나를 제거하고 플레이어 `bonuses`에 이동한다. 점수는 `color-bonus` 장부에 즉시 한 번만 반영된다. 종료 시 같은 타일 점수를 다시 더하지 않는다.

| 인원 | 1위 | 2위 |
|---|---:|---:|
| 2 | 5 | 2 |
| 3 | 6 | 3 |
| 4 | 7 | 4 |

기존 방패7 점수 배수, 수도원26, 3·4인 소진 후 보상 없음, 전체 스냅샷 Undo, 서버의 차례/리비전 검증과 원자 저장은 유지한다. 기존 보상 데이터는 새 필드나 마이그레이션 없이 읽는다.

## 증거와 검사

증거 루트 `.local-data/estate-bonus-assets/` (개인 방·로그/캡처는 Git 제외).

- `five-point-comparison.png`: 공통5 적용한6종
- `number-crops.png`: 숫자 영역6개 비교
- `number-outline-overlay.png`, `silhouette-overlay.png`: 같은 윤곽 중첩
- `all-36-variants.png`: 6종 × 숫자6종 전체 비교
- `alignment.json`: 실제 숫자 경계/중심/공통 레이어 해시
- `verified-browser/`: 최종 PC/Chrome 터치/WebKit, 공용2·3·4인/100·160·200%, 실제 개인 보상, 2위 공개, 온라인 새로고침 화면

검사 최종 결과는 `docs/PROGRESS.md` 최신 체크포인트에 기록한다. 최초 테스트의 건물 중복·튜플 타입 fixture를 보완했고, 브라우저에서 남은 주사위를 선택하지 않고 일꾼 획득을 누른 테스트 입력을 올바른 실제 조작으로 수정했다. 제품 규칙을 완화하지 않았다. 샌드박스의 임시 파일 rename EPERM은 격리 로컬 저장소 테스트를 일반 로컬 권한으로 실행해 검증했다.

최종 통과: **core515/515·boards33/33·타입·ESLint·프로덕션 빌드**, 에셋36장/공통 숫자6장 재현과 기존 타일 에셋 검증(경고0). **신규 브라우저18/18 + 기존 회귀16/16 + 기존 보상 검사1/1 =35/35**. 새 보상 검사의 서버 복원은 격리된 파일 저장소의 `RoomStore` 인스턴스를 재생성하여 양쪽 좌석의 보상을 확인한다. 실제 운영 Redis 재시작을 수행한 검사는 아니다.

최초 모바일 픽셀 검사1건의 불일치가 있어, PNG decode와 두 렌더 프레임을 기다린 뒤 캡처하도록 했다. 픽셀 완전 일치 기준은 그대로 유지했다. 집중3회 반복 및 최종 PC/터치/WebKit18개 검사 모두 통과했다. 반복 실행 수를 최종 통과 개수에 합산하지 않는다.

최종 직접 확인한 짧은 경로: `common-final-pc.png`, `common-panel-final.png`, `personal-final-mobile.png`, `online-final-iphone.png`. `verified-browser/`가 최종 검사 아티팩트이며, 앞선 실패/중간 캡처도 원인 추적을 위해 보존했다. 기존 공용/개인 보드 문구 외의 UI는 바꾸지 않았다.

실제 Android/iPhone 기기, 운영 네트워크/Redis/Render는 검사하지 않는다. 브라우저 모바일 에뮬레이션과 격리된 실제 서버 HTTP/저장소에 한정한다.
