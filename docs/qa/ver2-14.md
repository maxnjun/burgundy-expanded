## 시각 검증과 실패 원인 구분

- 실제 캡처에서 확인한 방패의 흰 덮임은 PNG 위 투명 rect에 적용된 legacy fill이었다. 원본 PNG·툴팁 규격은 그대로다. 비용 아이콘에는 공통 이동이 중첩돼 번호 가까이 올라가는 문제도 있어 보정을 일반 공급 타일에만 제한했다. 비용과 PNG 사이의 실제 화면 경계가 겹치지 않는지 검사한다.
- 최초 PC는 이전 UI 문구/버튼을 찾는 12건이 실패했다. 원래 검증 의도를 유지하도록 갱신한 뒤 전체 PC를 다시 실행하여 위 결과를 얻었다.
- 이름 검사의 409는 참가 완료 전 옛 revision으로 편집한 검사 경합이었다. 2/2 참가와 최신 revision을 기다린다. 비활성 행동 타일의 읽기 전용 설명은 실제 이미지 좌표를 터치해 검증한다.
- 신규 색상 수치 검사는 DPR1의 작은 이미지 재래스터화에서 평균 RGB 차이 **3.20**으로 한 건이 실패했다. 실제 흰 덮임은 보이지 않았고 필터/투명도 검사는 통과했다. 허용값 **평균 차이 3 / 질감 대비 15%**를 늘리지 않고 신규 수치 검사만 DPR2로 수행한다. 3엔진 2회씩 통과했으며 기존 DPR1 에셋/기능 회귀는 유지한다. PC/WebKit의 DPR1 18종 색상 검사도 통과했다. 실기기 검증으로 주장하지 않는다.
- `final-desktop-results/.../shield17-before-legacy-hover.png`는 이전 CSS를 잠시 적용한 **오류 재현**이며 과거 운영 캡처가 아니다. 같은 폴더의 `shield17-after-hover.png`, 공용/장착 100/160/200% 캡처에서 정상 그림과 번호를 직접 확인했다.
- `settings-capture-results/.../online-guidance-setting.png`: WebKit 모바일의 설정 패널·전체 조작 화면을 직접 확인했다. `free-vine-half-turn-preview.png`, `actual-die-tile-log.png`, `grape-token-picture-choice.png`, `actual-earned-castle-bonus.png`, `controls-resource-costs.png`도 각 최종 결과 폴더에 있다.

## 호환성·보존·백업

- `burgundy-local-v1`, 엔진 `0.2.1`, 방 저장 v1, 난수 상태·턴 스냅샷·요청 중복 방지 구조를 유지한다. 새 기록은 기존 `string[]` 안의 버전 표시 JSON이며 예전 일반 문자열도 읽는다. 구형 기록에 없던 눈금은 추측하지 않는다.
- 구형 시청은 정규 목록에서 포도만 빠진 정확한 선택지일 때만 읽기 과정에서 보완한다. 변조 선택은 거부한다. GET으로 Redis 원본을 덮어쓰지 않는다. 이전 판매를 무역로에 소급 추가하지 않는다.
