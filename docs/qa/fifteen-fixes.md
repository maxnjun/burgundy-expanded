## 저장·배포 준비

- 기존 v1 방/0.2.1 게임을 읽고 optional 공개 상품/보드ID/장착 출처를 사용한다. 게임 난수·타일/보너스 수량·기존 방/Redis는 초기화하지 않는다. 구형 출처는 임의 복원하지 않는다.
- 구형 서버는 새 장착 출처나 추가 반환 슬롯을 읽지 못할 수 있다. 향후 배포 후 이 저장 형식을 모르는 옛 바이너리로 무검증 롤백하지 않는다. 원본은 보존되며 자동 삭제/새 게임 초기화는 없다.
- `render.yaml`은 Auto-Deploy Off이며 기존 GitHub release는 `[no-deploy]`를 제외한다. 현재 운영 서비스의 실제 자동 배포 설정을 확인할 Render 인증은 없다. 따라서 **이번에는 Push도 보류**한다. 운영 배포·서비스 설정·유료 리소스 생성 없음.
- 이번 변경만 로컬 main 커밋에 `[skip render] [no-deploy]`를 붙여 보존한다. 운영 Auto-Deploy Off를 확인한 후 별도 Push/배포를 진행할 수 있다. 기존 무관한 dirty 문서꼬리·수도원27/28 PNG·입력 ZIP·asset-inbox는 커밋에서 제외한다.
- 다음 결정: 서로 다른 포도밭 보드 배정이 필요하면 추가 보드의 검증된 좌표·숫자·보상 데이터를 확보해야 한다. 사용자 승인 없이 커스텀 변형을 만들지 않는다.
