# 온라인 직접 조작·되돌리기·시작 성 확정

2026-10-23. 운영 Render Free/Upstash 설정 및 방 데이터는 변경하지 않는다. 코드 검증/Push와 실제 사이트 배포는 별도이며, 이번 커밋의 `[no-deploy]` 표시는 CI 후 자동 테스트 배포를 중지한다. 실제 배포는 사용자 확인 후 수행한다.

## 조작 방법

- 준비 완료·게임 시작 후 현재 차례인 사람만 시작 성 칸을 선택한다. 성이 임시 표시되고 다른 유효한 성 칸을 누르면 이동한다. `되돌리기` 또는 `이전 행동으로`는 임시 배치를 취소한다. `턴 종료`가 위치를 확정하고 다음 사람에게 넘어간다. 양쪽 확정 후 `주사위 굴리기`로 진행한다. 임시 위치도 서버에 저장되어 상대 화면/새로고침/재접속에 유지된다.
- 일반 행동은 주사위 선택 → 공급 타일 클릭, 저장고 타일 → 영지 칸 클릭, 상품 종류 클릭, 일꾼 획득 클릭으로 실행한다. 성 추가 행동·선박 상품 칸·방패 슬롯→성·포도 공급/배치도 기존 직접 클릭 컴포넌트를 쓴다. 행동 종류/실행 대상 드롭다운과 별도 `온라인 행동 실행`은 없다.
- 보관함 교체 등 필요한 입력은 먼저 대상을 고른다. 폐기 확인 등 기존 필수 확인은 유지한다. 보드로 선택할 수 없는 구체적인 효과/준비 행동만 해당 선택 버튼을 표시한다. 공급·방패·포도 위치별 행동을 중복 목록으로 나열하지 않는다.
- `이전 행동으로`: 마지막 독립 행동과 그 행동의 필수 연쇄 효과 전체를 취소한다. 반복 사용 가능하며 새 행동으로 분기하면 취소한 미래 기록은 폐기된다.
- `되돌리기`: 현재 차례 시작으로 복원한다. 주사위·사용 여부·난수 커서·은화·일꾼·점수/원장·상품/판매·영지/저장고·방패·포도밭·기타 확장 상태를 전체 스냅샷으로 복원한다. 자원을 역산하지 않는다.
- 사람의 턴은 자동 종료하지 않는다. 필수 행동/선택을 끝낸 뒤 `턴 종료`를 누른다. 상대 차례로 넘어가면 이전 턴은 되돌릴 수 없다.

## 서버 권한·안전 범위

기존 TurnHistory/recordTurnAction/undoTurn과 저장 검증을 재사용한다. 기록은 서버 Room JSON의 선택 필드이며 공개 RoomView에는 포함하지 않는다. 클라이언트는 `undo-turn`/`undo-action` 요청만 보내고 복원 상태는 제출할 수 없다. 본인 좌석·현재 턴·현재 revision을 서버가 확인하며 외부 Redis의 조건부 저장도 그대로 적용한다.

복원 시 게임 revision은 이전 값으로 낮추지 않고 현재 값+1로 갱신한다. 따라서 다른 브라우저가 복원된 최신 상태를 수신하고 오래된/중복 요청은409로 차단된다. 턴 전환/다른 플레이어의 후속 처리로 기록을 닫으며 새 무작위 결과가 공개된 행동 이전으로는 되돌리지 않는다. 라운드 주사위를 굴린 직후부터 첫 플레이어의 턴 시작을 기록하므로 주사위를 다시 굴리는 용도로 사용할 수 없다.

기존 방에 이번 차례의 시작 기록이 없으면 이를 임의로 만들지 않는다. 새로 수행한 독립 행동의 한 단계 복원은 가능하고 전체 턴 복원은 다음 정상 턴 시작부터 가능하다. UI에 서버가 비활성 이유를 제공한다. 기록이 방의 기존2.1MB 저장 한도를 넘으면 기록만 안전하게 초기화하고 현재 게임을 보존하며 제한 이유를 표시한다.

시작 성의 canonical 엔진 상태는 확정 전까지 그대로 두고 서버의 `startingPreview`만 바꾼다. 미리보기는 점수/효과를 발생시키지 않는다. `end-turn` 요청 시 서버가 미리보기를 검증된 기존 `place-starting-castle` 엔진 행동으로 변환한다. 기존에 확정된 시작 성/진행 중인 게임은 다시 setup으로 돌리지 않는다. 로컬/AI 시작 성 규칙은 이번 온라인 변경 대상이 아니다.

## 검증·배포

새 core/browser `online-controls` 검사, 기존 시작 성·방패·온라인 검사, 프로덕션 HTTP/WSS의 파일/Upstash REST 모의 저장소 검사에 반영했다. 실제 Lua/운영 방에는 테스트 데이터를 쓰지 않는다. 결과/실패 원인/후속 실행은 PROGRESS와 BUGS에 기록한다.

Push → Game CI 전체 검사 → release의 `[no-deploy]` 조건으로 배포 건너뜀을 확인한다. 사용자 배포 확인 뒤에만 검증된 SHA를 현재 Render 서비스에 적용하고 운영 사이트에서 두 좌석을 다시 검사한다. 새 리소스·유료 변경·기존 데이터 삭제는 필요하지 않다.
