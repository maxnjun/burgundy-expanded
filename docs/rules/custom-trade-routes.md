## 준비·진행
- 새 게임에서 무역로 확장 선택. 결정적 기존 RNG로 덱12장을 섞어 2/3/4인에게 각5/4/3장, 남은2/0/0장. 좌석 간 중복 없이 순서를 저장한다. 온라인 서버가 추첨하며 클라이언트가 카드를 제출하지 않는다.
- 상품 종류별 실제 판매 행동1회에 정확히1칸 진행한다. 판매 묶음의 상품 수와 무관하다. 일반 주사위와 흰 성 행동의 일꾼 보정은 기존 판매 검증을 따른다.
- 번호 일치 시 해당 보상, 불일치 시 뒷면/보상 없음. 양쪽 모두 다음 칸으로 이동한다. 전체 완료 후 일반 판매는 계속 가능하다.
- Ver.2 프로젝트 확정 규칙: 일반 주사위와 창고/성/흰 성/포도밭/무역로 보상에서 실행된 실제 판매 모두 종류별 판매 1회마다 경로 1칸을 진행한다. 공통 판매 처리에서 상품을 먼저 제거한 뒤 딱 한 번 진행하며, 보상 판매는 일반 주사위를 소비하지 않는다. 무역로 보상은 물리 건물을 생성하거나 배치하지 않는다.

## 보상
창고: 한 종류 판매. 목수 작업장: 일반 공급처 건물 획득. 교회: 성/광산/수도원 획득. 시장: 선박/가축 획득. 하숙집: 일꾼4(기존 방패 이벤트 포함). 은행: 은화2. 시청: 보관 타일 무료 합법 배치 및 원래 타일 효과. 망루:4VP 및 독립 점수 ledger. 흰 성: 현재 흰 주사위 눈으로 추가 행동, 기존 최소 일꾼 보정 허용.

선택형6종은 기존 immediateOptions/resolveTileChoice 및 서버 합법성 검사를 재사용한다. 남아 있는 실제 공급/보관 제한/교체 확인/추가 효과를 그대로 따른다. 효과를 사용하지 않을 때 기존 skip을 사용하고 상태를 skipped로 확정한다. 선택 확정 전에 pending이 유지되어 턴 종료를 막는다. 최초 선택에서 보상을 소비한 뒤 후속 물리 타일 효과를 처리하여 재사용을 방지한다. 흰 성 보상은 독립적으로 허용하되 물리 흰 성 확장을 자동 활성화하지 않는다.

## 저장·서버·AI
GameState.tradeRoutes는 version1, 플레이어별 tileIds(고정 순서), sales와 unusedTileIds를 저장한다. sales는 goodsType/goodsIds/revision/status(mismatch,pending,resolved,skipped)이며 현재 위치는 sales.length다. goodsIds는 기존 soldGoods 이력을 참조한다. 물리 상품을 복제하지 않아 수도원15/25 및 단일 소유권 검사를 보존한다.

카드 전수/좌석/중복, 단계별 판매 이력의 상품/리비전, 보상 종류/상태, 선택 대기 소유자 및 망루 점수 ledger를 파서가 검사한다. 확장 없는 과거 저장은 그대로 복원하고 카드를 임의로 추가하지 않는다. 서버가 기존 GameAction/좌석/리비전으로 원자적으로 판매·보상을 처리하고 공개 상태/재접속을 동기화한다. 직접 상태 제출과 상대 좌석 행동/동일 리비전 재전송은 거부한다.

AI는 직접 판매 평가에 다음 칸의 번호와 보상별 가치를 더하고 기존 합법 선택 엔진으로 보상을 해결한다. 2/3/4인 25라운드 및 중간 저장 복원을 검사한다.

## UI와 보존 범위
개인 영지 아래 공통 TradeRoutePanel. 기본 현재1장/3칸, 전체 펼치기, 다음 칸 금색, 선택 대기/완료/사용 안함/불일치 구분, 카드 자동 전환 및 마지막 완료 유지. 그림은 기존 GoodsArt/TileArt, 뒷면은 자체 SVG. 공용 보드/여관/타일 이미지/프레임/영지 좌표/게임 규칙은 바꾸지 않는다. 기존 방패9→수도원3의 은화 계산 뒤 은행 보상2를 한 번 더한다.

기존 `trade-routes.ts`의 공식 자료 기반 순수 기초 모듈과 TEST FIXTURE는 보존하지만 런타임의 판매 진행에는 사용하지 않는다(그 모듈의 결정적 카드 배분만 재사용). 공식 36칸 자료 미확보와 사용자 커스텀 데이터 구현 완료는 구분한다.
