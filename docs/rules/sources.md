## 3. 증거와 설계의 구분

이 절의 '실행 가능한 규칙 엔진 없음'은 초기 타입 설계 단계의 기록이다. 이후 추가한 부분 핵심 엔진과 규칙별 구현 범위는 [core-engine.md](../core-engine.md), 실제 테스트·빌드 결과는 [development-progress.md](../development-progress.md) 9절을 따른다. 공식 카탈로그와 전체 기본판이 완성된 것은 아니다.

[base-game.md](base-game.md)는 확인한 기본판 규칙을 페이지와 함께 요약한다. [unresolved.md](unresolved.md)는 보드 데이터 미확보, 해석 미확정 및 구현 정책 미결정을 구분한다. 타입의 식별자·상태 단계·이벤트·seed는 소프트웨어 설계이며 공식 규칙의 직접 인용이 아니다.

이번 단계에는 실행 가능한 규칙 엔진, 검증 완료 타일 카탈로그, 영지 맵, 확장 구현이 없다. 공식 문서를 읽었다는 사실과 모든 조합을 검증했다는 주장은 구분한다.

## 13. 솔로 라운드/선박 구성 요소 (2026-10-18)

공식 p.16의3주사위, 흰 주사위 상품 배분/육각 타일 제거와 시계방향 대체, 선박 상품 전량 수령·타 공급처 상품 폐기·상품5개 교환을 solo-round.ts/solo-ship.ts로 분리했다. 슬롯 배열 순서를 물리 제거 순서로 추정하지 않았으며, 실제 검수할 제거 계획은 주입한다. 거꾸로 배열한 TEST FIXTURE로 순서 독립성을 검사했다.

상품5개로 뒤집어 받은 검은 타일은 wildTileIds로 별도 식별한다. 은화로 산 검은 뒷면/색 완성 보상의 앞면 타일까지 무효과로 간주하지 않는다. 와일드 선박의 효과 재발동을 차단하고 실제 상품/타일 폐기 이력을 보존한다. 단일 솔로 상태·강 연결 배치·와일드 전체 수입/득점 제외·색 완성 직접 배치·수도원 즉시 득점·저장/UI 통합은 후속 작업이다.

p.10은 판매 시2/3/4인 점수를 명시하고 p.16은 기본 규칙을 참조한다. 솔로 적용 수치는 통합 전에 추가 대조 중이며 아직 판매 행동을1점/2점으로 하드코딩하지 않았다. 관련 [BGG 솔로 규칙 토론 목록](https://boardgamegeek.com/boardgame/264104/the-castles-of-burgundy-10th-expansion-solo/forums)과 검색 결과에는 구판/샤토마/카드게임/팬 변형이 섞여 있어 권위 있는 확인 없이 전용하지 않는다. 상세 현황은 ../solo-components.md와 ../PROGRESS.md다.

## 14. 방패 공용 보드 UI 및 획득 부분 구현 (2026-10-18)

- 프로젝트 로컬 공식 자료 `reference/official-rulebook-public.pdf` p.17:18개 섞기,2인 각 공급처1개/3인1·3·5번1개와2·4·6번2개/4인 각2개. 남는 방패는 상자에 보관하며 획득한 슬롯은 **보충 없음**.
- p.17: 두 주사위를 같은 공급처 눈으로 맞춰 두 행동 대신 방패 획득, 일꾼 보정 가능, 자기 성 위 장착 또는 기존 방패를 완전히 제거하고 교체. 단계 말 광산 수입 전 방패당 은화1 유지비 규칙도 확인했지만 이번 UI 부분 구현에는 미연결이다.
- p.18:18종 능력 이름과 종료 점수 구분을 SVG/선택 도움말에 표시한다. 능력·유지비·종료 점수 미구현이므로 `uiPreview:true`와 `effectsActive:false`인 로컬 UI 검증 모드다. 이를 공식 방패 확장 플레이 가능으로 보고하지 않는다.
- 위치는 이번 사용자 표시 스크린샷의 여섯 그룹 의도를 따르는 자체 SVG이며 공식 보드 이미지나 BGA 자산을 복사하지 않았다. 인원수가 늘어도 여섯 공급처 대응과 각 슬롯 ID를 유지한다.

## 15. 방패18종 활성 규칙 연결 (2026-10-18)

- 기본 근거는 동일 공식 PDF p.17~18. 활성 모드는 shield-rules-v1/rules:true로 구별하고 기존 uiPreview:true 파일을 자동 승격하지 않는다.
- p.17의 광산 수입 전 유지비를 실제 선택 창으로 처리한다. p.18의14/15는 행동 종료 후 직접 배치 및 타일 효과를 먼저 처리하고, 이후 유지비·광산 수입·E 종료 점수를 처리한다. 같은 플레이어가14/15를 모두 갖는 경우 처리할 방패를 선택한다. 무한 보관4 제거 시 세 칸 초과분의 폐기 타일을 직접 고르게 한다.
- p.18의6은 지정 플레이어의 **실제 배치된 수도원**을 참조하고27을 제외한다. 방패6의 재귀 복사나 상대 영지 건물 수로 자기 점수를 계산하지 않는다. 대상 선택/16 차례별 사용/단계 처리 이력은 저장 상태에 포함한다.
- 종료 점수는1~6번12점,7~12번8점,13~18번4점.13은 자신을 포함한 소유 방패 종료 점수를 두 배로 계산하며10은 수도원 종료 점수에만 적용한다. 미유지/교체 제거된 방패에는 적용하지 않는다.
- 추가 공개 조사: [출판사 FAQ](https://support.awakenrealms.com/support/solutions/folders/42000113449)는 HTTP 접근 가능했으나5개 항목 모두 캠페인/배송/결제 내용이었다. [단계 말 방패 규칙 토론](https://boardgamegeek.com/thread/2643893/question-regarding-of-shields-and-phase)은403으로 읽지 못했다. 접근 제한을 우회하지 않았다.
- 검색에 방패9+수도원3 합성 질문이 확인되지만 공식 답변을 확보하지 못했다. 당시 두 은화 대체 규칙의 결과를 추측하지 않고 해당 조합의 판매만 unresolved-rule로 거절했다(U15). 현재는 아래 사용자 확정 프로젝트 규칙으로 차단을 해제했다. 개별18종 처리 완료와 모든 조합/전체 확장 검증 완료는 구별한다.

## 흰 성·수도원29 검증 (2026-10-19)
- 1차 자료: `reference/official-rulebook-public.pdf` p.3(9개 구성), p.12(16–23+29 건물별4점), p.13(기중기: 모든 베이지 건물 효과·종료16–23+29 중 한 종류), p.14(공급에 혼합, 흰 주사위 현재 눈 추가1행동, 일꾼 보정 허용, 실제 흰 주사위 불변).
- 수량·뒷면 교차 확인: 공식 `reference/official-se-acrylic-stickers-en.pdf` p.5(흰 주사위 행동 라벨: 베이지6·검정2), p.6(노랑 수도원29: 흰 성마다4점). 원문 페이지를 렌더링해 직접 확인했다.
- 흰 성은 building/white-castle, 건물 지형·도시별 같은 종류 제한을 적용한다. 녹색 성/방패 장착 대상으로 취급하지 않는다. 수도원29는 자신 영지의 배치된 흰 성만 센다. 기중기는 즉시 선택과 별개로 종료 때 유리한 한 건물로 세며, 여러 수도원에 중복 산입하지 않는다.
- 선택 확장 `white-castles`의9개를 각 뒷면·종류 공급에 섞는다. 기존 기본/추가 타일 설정과 저장은 그대로 유지한다. 3·4인 공급 전체는 기존 연습 구성이라는 제한을 유지한다.
- 공식 자료 출처는 기존 Awaken Realms 다운로드 목록과 저장된 공식 PDF다. 팬 게시물은 구현 근거로 사용하지 않았다. 새 타일 그림·테두리는 제작하지 않고 기존 공통 건물/수도원 렌더러와 설명을 재사용한다.
