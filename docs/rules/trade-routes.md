# 무역로 확장 — 검증된 규칙과 구현 경계

2026-10-19. **기초 모듈만 구현. 실제 게임 확장/보상 지급은 아직 미구현이며 활성화할 수 없다.** 여관 코드·그림·공용 보드·배경은 변경하지 않았다.

## 확인된 준비·진행
- 타일당3칸. 2인은 각5장(15칸), 3인은 각4장(12칸), 4인은 각3장(9칸)을 무작위 선택하고 무작위 순서로 연결한다. 2인에서는2장이 남는다.
- 기본은 무작위 순서이며 선택 규칙으로 본인이 순서를 고를 수 있다. 선택 규칙 UI는 아직 구현하지 않았다.
- 상품 한 묶음을 판매하면 상품을 한 개씩 왼쪽부터 채운다. 현재 칸 번호와 판매 상품 번호가 일치하면 표시된 보상을 즉시 받는다. 불일치 상품도 한 칸을 차지한다.
- 경로가 가득 차면 초과 상품은 일반 판매 상품 더미로 간다. 보상 일치 판정과 실제 보상 지급은 별도 단계다.
- 일반 판매의 은화/승점은 기존 규칙을 유지하는 방향으로 연결한다. 구체적인 추가 보상 값이나 종료 점수를 새로 추정하지 않았다. 규칙서14페이지에는 별도의 무역로 종료 점수표가 없다.

## 구현한 코드
- `src/game/trade-routes.ts`: 주입된12장 카탈로그의 구조 검사, 기존 counter-v1 RNG로 편향 없는 Fisher–Yates 추첨, 플레이어별 배분/잔여 타일, 좌→우 판매 상품 배치, 일치 보상 참조 반환, 경로 초과 상품, 동일 상품 재전송 거부, JSON 왕복 후 위치·일치 이력 검사.
- `matchedSpaceIds`는 일치 이력일 뿐 보상 지급 완료가 아니다. 보상 종류/수량을 알 수 없으므로 `bonusId`는 해석하지 않는 참조이며 엔진 자원/점수를 변경하지 않는다.
- 공식 카탈로그 `VERIFIED_TRADE_ROUTE_CATALOG`는 빈 배열로 유지했다. 구조 검사를 통과하는 자료가 공식 검증 자료라는 뜻은 아니다. 배포용 준비는 검증된 실물 데이터에 연결해야 한다.
- `tests/core/trade-routes.test.ts`: **TEST FIXTURE ONLY**인 가상12장으로7개 검사. 가상 데이터를 실제 게임/공식 타일로 등록하지 않았다.

## 상품 판매·확장·온라인 연결 설계 (미구현)
1. 검증 카탈로그에 타일별3칸 번호와 실제 보상/선택/연쇄 의미를 등록한다. 먼저 최소12장 모두의 구조·보상 검증을 추가한다.
2. 게임 준비/온라인 방 생성 옵션과 서버 난수 추첨을 연결한다. 배분 타일은 좌석 간 중복되지 않게 서버가 소유권까지 검사한다. 옵션이 없는 과거 저장은 그대로 둔다.
3. `src/game/core/intents.ts`의 공통 `sell-goods` 경로에 연결한다. 주사위 직접 판매뿐 아니라 창고·성·흰 성·기중기 등의 추가 판매도 같은 경로를 거친다.
4. `soldGoods`는 수도원15/25 등에서 이미 판매 이력으로 쓰고 있다. 무역로에 놓인 상품을 이 목록에서 단순 삭제하면 보너스가 깨진다. 물리적 위치와 전체 판매 이력을 분리하고 상품 ID는 저장의 단일 위치 검사에서 중복 계산하지 않아야 한다.
5. 기존 `goodsSaleReward`의 방패9→수도원3 계산은 유지한다. 무역로 일치 보상을 기존 판매 보상에 다시 곱하거나 판매 묶음을 여러 번 계산하지 않는다. 일꾼 보상은 방패2 이벤트를, 상품 선택/추가 행동 보상은 기존 필수 선택 흐름을 검토해 원자적으로 실행해야 한다.
6. 실제 보상을 알고 난 뒤 저장 파서/공통 GameAction/로그/점수 ledger, AI 판매 평가와 온라인 공개 상태/재접속에 연결한다. 보상 미해결 상태에서 자동 턴이 넘어가지 않게 한다.
7. 개인 영지 아래 진행 패널을 추가한다. 공용 보드와 타일/여관 그림을 바꿀 이유는 없다. 현재는 작동하지 않는 활성화 UI를 추가하지 않았다.

## 필요한 자료와 다음 작업
- **무역로12장 전체 앞면**: 각 타일의3칸을 왼쪽부터 읽을 수 있는 번호/보상 아이콘/수량. 한 장의 선명한 전체 사진이나 이 정보를 모두 담은 표도 가능하다.
- 보상 아이콘의 정확한 뜻: 상품/타일을 직접 얻는지 선택하는지, 추가 판매/행동의 조건·보정 가능 여부 등. 사진만으로 불명확하면 공식 설명 또는 사용자 확정 판정이 필요하다.

- 다음 시작 파일: 이 문서→검증된 카탈로그 파일 신설→`trade-routes.ts` 보상 해석→`core/intents.ts`/`state.ts`/`save.ts`→준비·진행 UI→AI/서버→모드별/브라우저 검사. 여관 작업으로 돌아가지 않는다.
