## 점수·저장·호환

- 23~30번을 고르면 별도 확장 체크 없이 자동 적용한다. 1~22번에는 적용하지 않는다.
- 줄의 모든 실제 칸 ID가 채워지는 순간 현재 단계의10/8/6/4/2점을 각각 지급한다. 일반 지역/색상 점수와 독립이며 공통 단계 점수 상수를 사용한다.
- 완료 지급 ID는 `fortress:{playerId}:{boardId}:{lineId}`다. 기존 완성 여부 비교와 ledger 고유 ID를 함께 검사해 재전송·추가 행동·단계 변경에 중복 지급하지 않는다. 점수 기록 자체가 지급 완료 상태이며, 실제 칸으로 완성 여부를 다시 검증한다.
- 로컬/AI/온라인 모두 같은 placement 함수를 사용한다. AI는 해당 점수까지 포함한 기존 배치 평가를 사용한다. 온라인은 서버가 계산하고 공개된 요새 기록만 양쪽에 전송한다.
- 기존 저장 버전·기존 점수는 유지한다. 과거 연결 방식으로 받은 `border:*` 점수는 삭제하거나 재계산하지 않는다. 새 규칙 적용 전에 이미 채워져 있던 줄은 소급 지급하지 않고 ‘기존 완성’으로 표시한다. 이후 새로 완성한 줄만 지급한다.
- 옛 연결 판정 유틸/테스트는 역사적 회귀용으로 보존했지만 현재 배치 엔진은 호출하지 않는다. 과거 ‘전체 연결 선착순’ 보너스를 새 줄 완성에 덧붙이지 않는다.

## 임시 아이콘과 PNG 교체

공통 컴포넌트는 `src/app/fortress-markers.tsx`다. `FORTRESS_ICON`의 `imagePath`, `size`, `offsetX`, `offsetY`로 표시만 조정한다. 예약 경로는 `/tiles/fortress.png`이며 나중에 `public/tiles/fortress.png`를 추가하면 된다. 다른 이름이면 경로 설정만 바꾼다.

파일이 없거나 로드 실패/지연이면 임시 SVG를 유지한다. PNG는 사전 로드 성공 후에만 SVG에 삽입해 깨진 이미지 표시를 방지한다. 점수·칸 좌표·아이콘 클릭 영역은 이미지 로드와 무관하다. hover/클릭/키보드로 대응5칸을 강조한다. 아이콘은 타일 선택 영역이 아니며 40×40 외곽 영역을 갖는다.

## 랜덤 후보2개

- 게임 준비에서 ‘랜덤 후보2개 중 영지 선택’을 켠다. 기존 수동 선택 방식도 유지한다.
- 각 좌석이 기본1~22 / 요새23~30 / 전체1~30 범위를 선택한다. 등록·검증된 보드만 사용하며, 기존 counter RNG의 균등 rejection sampling으로 서로 다른2개를 추첨한다.
- 미리보기는 실제37칸 데이터와 숫자를 표시한다. 후보 중 하나를 선택하고 모든 활성 좌석의 선택이 끝난 후 시작한다. AI 좌석은 두 후보 중 지역 구조 점수를 기준으로 자동 선택한다.
- 로컬 후보/범위/선택/RNG cursor는 `burgundy-expanded:board-draft-v1`에 저장한다. 새로고침은 재추첨하지 않는다. 선택이 잘못된 저장은 조용히 덮어쓰지 않고 오류를 표시한다.
- 온라인 방 생성에서 랜덤 선택을 켜면 서버가 후보를 만들고 방 파일에 저장한다. 각 좌석은 자기 범위·자기 후보만 선택할 수 있다. 양쪽 선택이 완료될 때 선택 영지로 게임 상태를 만들며, 그 전에는 어떤 게임 행동도 실행하지 않는다.
- 온라인 후보 RNG는 클라이언트에 보내지 않는다. 인증 좌석·revision·범위·후보 소속을 서버에서 검사한다. 다른 좌석/위조 후보/오래된 요청은 거부하고, 완료 후 재선택도 거부한다. 기존 랜덤 선택 없는 방과 기존 게임 시작 경로는 유지한다.
