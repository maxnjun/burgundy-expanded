# 여관(Inns) — 사용자 확정 프로젝트 규칙

이번 구현은 사용자 지시문과 후속 답변을 기준으로 한다. 출판사 공식 판정이라는 뜻이 아니며 공식 자료를 추가 검색하지 않았다.

## 공급과 구매
- `inns` 옵션을 켠 새 게임에서만 공급한다. A–E 시작마다 고유 ID `project:inn:{phase}` 1개, 총5개. 미획득 타일은 이월한다.
- `market.inns.suppliedPhases`와 `stack`에 공급 이력/남은 ID를 저장한다. 총수/잔여수는 각각 배열 길이이며 별도 중복 수량 필드를 두지 않는다. phase 전환 재전송으로 다시 공급하지 않는다.
- 사용자 답변: “은화 2개로 검은타일처럼 사는거야. 그래서 옆에 배치하는거고.”
- 기존 `buy-black-tile` GameAction을 재사용한다. 은화2·주사위 없음·검은 구매와 `blackPurchaseUsed` 턴당1회 제한 공유. top 타일1개만 획득한다. 보관함 교체 시 기존 명시적 폐기 확인을 유지한다.
- 기존 검은 공급처/예약 풀에 여관을 섞지 않는다. 남은 스택·보관·배치·폐기의 유일한 위치를 검증한다.

## 조커와 점수
- 실제 6색 지형/숫자/지역 ID/인접 칸은 그대로 둔다. 여관은 어떤 지형에도 배치하지만 주사위 숫자·일꾼·인접 조건을 지킨다(기존 방패18 예외 유지).
- 같은 지역 ID에는 여관 최대1개. 다른 같은색 지역은 각각1개 가능하다. 여관은 별도 `inn` 타입이며 건물 중복 종류로 취급하지 않는다.
- 성 추가행동, 선박 이동/상품, 광산 수입, 가축 점수, 건물/수도원 고유 능력을 부여하지 않는다. 그림의 포도밭은 장식이다.
- 실제 지역 칸이 모두 차야 완성된다. 점수 계산 크기 = 실제 크기 + (여관 유무 ? 1 : 0) + (방패17 유무 ? 1 : 0). 기존 삼각 점수 n(n+1)/2를 사용한다.
- 실제 크기1–8을 유지하며, 여관/방패17 합산 최대 점수 크기10은55점으로 명시 처리한다. 크기9는45점. +1은 빈 칸이나 실제 영역/줄의 크기를 늘리지 않는다.
- 단계10/8/6/4/2점·지형 전체 완성·요새 줄 완성은 독립이다. 기존 completedRegionIds/scoreLedger 중복 방지를 그대로 사용한다. 여관 관련 크기 점수/행동 source는 `project-user-rule`로 기록한다.
- 여관에 지형별 고유 능력을 부여하지 않으므로 수도원9/10/11의 특정 타일 종류별 무료 보정도 자동 추가하지 않는다. 일반 일꾼 보정과 기존 공통 효과를 사용한다.

## 이미지와 화면
- 원본: `public/tiles/originals/inn-user-original.png` (RGB1312×1199), SHA256 `52ec2030ce6c10affb9d46ac78e426bbc9912234d58ecf358f1be4c68804c01e`.
- 파생: `public/tiles/inn.png` (RGBA1312×1199), SHA256 `d2f3303b6d8b05e3facc53e1a2c38bbc8674197a0740c8ec77dd47c97b1fabb8`. imagegen 외부 배경 제거. 중앙 여관·색상 방사형 디자인/금색 rim 유지, 다른 타일 이미지 수정 없음.
- 모서리4개alpha0. alpha>128 콘텐츠 bbox는(95,2)–(1208,1199). `InnArt`가 이 측정값을 공통 육각형 viewBox(폭100,높이200/√3)로 맞추고 같은 육각 마스크로 클리핑한다. 원본의 비정규 육각 비율을 게임 좌표로 정규화하며 추가 SVG 프레임은 그리지 않는다.
- `INN_STACK` 설정: 중심(215,398), 폭40, 층 오프셋(-1.4,+1.8). 모든 층은 실제 같은 PNG를 쓰며 기존 검은 마름모 좌표는 불변이다. 비용/수량은 빈 공간의 작은 배지로 분리한다.
- 하나의 union path가 노출된 모든 층의 실제 육각형 영역을 포괄한다. 장식/하위 이미지는 pointer-events:none. 빈 스택은 획득 불가. PNG 오류/지연 실패는 자체 SVG 여관으로 대체한다.
- 로컬 공용/보관/영지와 온라인 스택이 같은 TileArt/InnArt를 쓴다. `hasTileFrame`에 여관을 등록해 EstateGrid의 중복 테두리를 숨긴다. 다른 타일의 공통 프레임은 유지한다.

## 저장·AI·온라인
- schemaVersion과 기존 저장 형식을 바꾸지 않는다. 옵션 없는 과거 저장에는 여관을 넣지 않는다. 여관 ID·유일 위치·공급 단계·같은지역 중복을 검증하고 잘못된 데이터는 거부한다.
- AI는 엔진 합법 행동만 사용하며 조커 가용 칸과 보관 중복/점수 가치를 평가한다. 배치 평가에는 실제 추가 지역 점수가 포함된다.
- 서버가 옵션/공급/구매/배치/점수/좌석/리비전을 검사한다. 공개 응답은 이미 공급된 여관만 포함한다. 랜덤 영지 선택 완료 후에도 여관 옵션을 유지한다.
- 현재 검증: 전체코어335/335·보드33/33, 신규 여관24개(이 중 온라인1개), AI2/3/4인25라운드·확장 조합·저장 복원, PC신규9개·기존19개 회귀. 모바일 정밀 QA는 최종 통합 단계로 보류한다.
