# Burgundy Expanded UI 레이아웃 명세

- 상태: 다음 UI 구현 단계를 위한 설계 요구사항
- 작성일: 2026-10-17
- 적용 대상: 최종 게임 화면, 2~4인 게임
- 이번 변경 범위: 이 문서만 작성. 실제 UI 및 v0.2.1 규칙 엔진은 변경하지 않는다.

## 1. 목적과 기본 구조

중앙 공용 보드와 모든 플레이어의 개인 영지 보드를 한 페이지에 펼쳐 놓는다. BGA의 공용·개인 보드 병렬 구조는 참고하되, 코드·이미지·보드 그래픽은 복제하지 않는다. 현재 v0.1의 자체 SVG와 아이보리 `#F4EFE5`, 네이비 `#172437`, 골드 `#C7A66B` 디자인을 이어간다.

공용 보드는 공급처 등 공용 게임 상태를, 개인 보드는 해당 플레이어의 영지와 관련 상태를 보여준다. 레이아웃 변경, 확대·축소, 이동은 표시 상태만 바꾸며 게임 상태·차례·선택을 변경하지 않는다. 차례가 바뀌어도 ‘내 플레이어’의 식별자는 바뀌지 않는다.

페이지 구성:

1. 상단: 게임명, 단계·라운드, 현재 차례, 레이아웃 및 전체 보기 제어.
2. 보드 영역: 공용 보드와 2~4개의 개인 영지 보드.
3. 보드별 헤더: 보드명, 소유자, 점수·핵심 자원, 개별 보기 제어.
4. 선택 상세 및 행동 기록: 같은 페이지에서 접근 가능한 독립 패널.

## 2. 레이아웃 모드

### 2.1 전체 보드 모드 (`overview`)

- 공용 보드와 모든 플레이어의 영지를 동시에 렌더링한다. 플레이어 전환 탭으로 영지를 대체하거나 숨기지 않는다.
- 2인, 3인, 4인 게임에서 각각 해당 수의 영지를 표시한다.
- 가용 너비에 맞는 반응형 그리드를 사용한다. 넓은 화면은 공용 보드와 개인 보드를 여러 열로, 좁은 화면은 더 적은 열 또는 세로로 배치한다.
- 보드를 읽을 수 없을 정도로 축소해서 한 화면에 강제로 넣지 않는다. 모든 보드는 같은 페이지에 유지하고, 넘치는 내용은 스크롤로 접근한다.
- ‘동시에 표시’는 모든 보드가 페이지에 존재한다는 의미이며, 모든 화면 크기에서 스크롤 없이 보이는 것을 보장하지 않는다.
- 보드 순서는 공용 보드 → 내 영지 → 상대 영지(고정 좌석 순)로 유지한다. 자동 배치도 이 순서를 바꾸지 않는다.

### 2.2 내 보드 중심 모드 (`focus`)

- 공용 보드와 내 영지를 상단의 주 영역에 크게 표시한다.
- 넓은 화면에서는 두 보드를 나란히, 좁은 화면에서는 공용 보드 다음에 내 영지를 배치한다.
- 상대 영지 전부를 같은 페이지 아래쪽에 배치한다. 아래로 스크롤하여 각 보드를 확인한다.
- 상대 보드도 선택·상세 확인과 개별 보기 제어를 지원한다. 실제 행동 가능 여부는 규칙 엔진이 판단한다.
- 현재 차례의 플레이어를 내 플레이어로 간주하지 않으며, 차례 전환으로 상단 영지를 교체하지 않는다.

## 3. 확대·축소와 보드 이동

### 3.1 배율 모델

전체 배율과 개별 배율을 독립적으로 유지한다.

| 항목 | 범위 및 단위 | 적용 대상 |
| --- | --- | --- |
| 전체 배율 | 50~200%, 1% 단위 | 모든 보드의 도면 영역 |
| 개별 배율 | 각 보드 50~200%, 1% 단위 | 공용 보드 또는 특정 개인 보드 |
| 초기값 | 전체 100%, 개별 100% | 별도 저장값이 없을 때 |

- 표준 보드 크기에 전체 배율과 개별 배율을 곱해 표시한다. 따라서 두 제어값이 모두 200%이면 실제 표준 크기 대비 400%가 될 수 있다. 제어값은 각각 50~200% 범위를 지킨다.
- 전체 배율은 모든 보드 도면에 동일하게 적용하되, 페이지 헤더·보드 헤더·제어 버튼·점수·상세 패널을 함께 축소하지 않는다.
- 개별 배율 변경은 다른 보드의 개별 배율이나 전체 배율을 변경하지 않는다.
- 숫자 입력 또는 슬라이더로 1% 단위 조절을 제공하고, −/+ 버튼은 5% 단위로 조절한다. 범위 경계에서 값을 제한한다.
- 전체 도면의 크기 변화가 스크롤 영역의 실제 크기에 반영되어야 한다. CSS 변형만 적용하여 확대된 끝부분에 접근할 수 없는 상태를 만들지 않는다.

### 3.2 마우스 휠

- 일반 휠은 페이지·보드 영역의 스크롤을 유지한다.
- 보드 도면 위에서 `Alt + 휠`은 해당 보드의 개별 배율을 변경한다. UI에 이 조작법을 표시한다.
- 전체 배율 제어 영역에서 `Alt + 휠`은 전체 배율을 변경한다.
- 배율 변경을 처리할 때만 기본 스크롤을 막는다. 브라우저 기본 `Ctrl/Cmd + 휠` 확대 기능은 가로채지 않는다.
- 포인터 아래의 보드 위치를 기준으로 확대하여 사용자가 보고 있던 타일을 유지한다.
- 트랙패드의 작은 입력은 누적·정규화하여 갑작스러운 배율 점프를 방지한다.

### 3.3 드래그 이동

- 보드의 빈 배경 드래그 또는 `Space + 드래그`로 해당 보드를 이동한다.
- 클릭과 드래그는 이동 임계값(예: 5 CSS px)으로 구분한다. 드래그 종료 시 타일 선택·배치 클릭이 발생하지 않아야 한다.
- 포인터 캡처를 사용하고, 포인터 취소·창 포커스 상실 시 이동 상태를 해제한다.
- 보드가 완전히 화면 밖으로 사라지지 않도록 이동 범위를 제한한다.
- 이동은 각 보드의 뷰포트 내부에서 처리하며 페이지 자체를 드래그하지 않는다.
- 터치에서는 보드 배경 드래그로 이동할 수 있게 하되, 페이지 스크롤을 위한 보드 바깥 여백을 제공한다. 버튼 기반 확대와 스크롤만으로도 모든 보드에 접근할 수 있어야 한다.

### 3.4 화면에 맞추기와 초기화

| 제어 | 동작 |
| --- | --- |
| 전체 화면에 맞추기 | 현재 레이아웃을 유지한 채 전체 배율을 계산하고 각 보드의 이동을 중앙으로 정렬한다. 개별 배율은 유지한다. |
| 개별 보드 맞추기 | 해당 보드의 현재 뷰포트에 도면이 들어오도록 개별 배율을 계산하고 해당 보드 이동만 중앙으로 정렬한다. |
| 전체 확대율 초기화 | 전체 배율만 100%로 되돌린다. |
| 개별 보드 초기화 | 해당 보드의 개별 배율을 100%로 되돌리고 이동을 중앙으로 정렬한다. |
| 모든 보기 초기화 | 명시적 별도 버튼으로 전체·개별 배율을 100%로 되돌리고 모든 이동을 중앙으로 정렬한다. 선택한 모드와 자동 레이아웃 설정은 유지한다. |

- 전체 맞추기는 전체 보드 모드에서 전체 보드 묶음, 내 보드 중심 모드에서 상단 공용 보드와 내 영지를 기준으로 한다. 후자의 상대 영지는 아래쪽에 유지한다.
- 맞추기 계산에는 헤더와 도구 모음의 공간을 제외한다. 가능한 배율이 50%보다 작으면 50%로 제한하고 스크롤을 허용한다.
- 맞추기는 사용자의 명시적 일회성 동작이다. 이후 화면 크기가 바뀐다는 이유로 저장된 수동 배율을 계속 덮어쓰지 않는다.
- 배율 변경 또는 모드 변경만으로 타일 선택을 해제하거나 게임 행동을 실행하지 않는다.

## 4. 자동 레이아웃

- 기본값은 비활성화다. 사용자가 활성화한 경우에만 화면 크기·플레이어 수·확대율을 입력으로 열 수와 보드 배치를 자동 최적화한다.
- 자동 최적화는 선택된 모드 안에서 수행한다. `overview`와 `focus`를 임의로 전환하지 않는다.
- 자동 모드에서는 보드의 배율 적용 후 크기와 최소 가독 너비를 고려하여 열 수를 줄이거나 늘린다. 전부 맞출 수 없다면 스크롤을 유지한다.
- 자동 레이아웃은 사용자가 지정한 전체·개별 배율을 임의로 변경하지 않는다.
- 비활성화 상태에서는 선택된 모드와 기본 반응형 구조를 유지한다. 좁은 화면에서의 기본 열 접기와 스크롤 처리는 허용하지만, 확대율을 이유로 모드·순서·사용자 선택을 바꾸지 않는다.
- 확대·축소 중 반복 재배치나 화면 떨림이 발생하지 않도록 입력 종료 후 재계산하고, 열 수 전환에 여유 구간을 둔다.
- 자동 레이아웃을 켜거나 꺼도 기존 모드와 보드별 배율은 유지한다.

## 5. 설정 저장

브라우저 `localStorage`에 보기 설정만 저장한다. 게임 진행 상태 저장과 분리한다.

제안 키: `burgundy-expanded:ui-layout:v1`

```json
{
  "version": 1,
  "layoutMode": "overview",
  "globalZoom": 100,
  "boardZooms": {
    "shared": 100,
    "player:seat-1": 110,
    "player:seat-2": 100
  },
  "autoLayout": false
}
```

- 개인 보드 키는 렌더 순서·이름·현재 차례 대신 안정적인 플레이어/좌석 식별자로 생성한다. 예시의 `seat-1`은 UI 어댑터의 예시이며 규칙 엔진 스키마를 강제하지 않는다.
- 저장 대상: 선택한 레이아웃, 전체 배율, 공용·개인 보드별 배율, 자동 레이아웃 여부.
- 드래그 이동 좌표, 선택 타일, 게임 행동과 점수는 이 설정에 저장하지 않는다.
- 서버 렌더링 중 `window`나 `localStorage`에 접근하지 않는다. 클라이언트에서 저장값을 복원한 뒤 저장을 시작하여 초기 기본값으로 기존 설정을 덮어쓰지 않는다.
- 값 변경 후 짧은 지연으로 저장을 묶는다. 재접속·새로고침 후 유효한 설정을 복원한다.
- 파싱 실패, 알 수 없는 버전·모드, 잘못된 자료형은 기본값으로 복구한다. 유한한 숫자 배율은 정수화하고 50~200으로 제한한다.
- 저장 접근 실패·저장 공간 부족·차단 환경에서도 메모리 상태로 정상 동작한다.
- 현재 게임에 없는 플레이어의 보드 설정은 렌더링에 사용하지 않는다. 새 플레이어는 개별 배율 100%로 시작한다.
- 다른 탭의 저장 변경이 현재 보기를 갑자기 이동시키지 않도록 실시간 탭 간 동기화는 이번 범위에서 제외한다.

## 6. 가독성과 접근성

- 상단·보드별 도구 모음은 도면 확대와 분리된 고정 CSS 크기로 렌더링한다.
- 점수·자원·플레이어 이름·현재 차례·선택 상세는 50%에서도 보드와 함께 작아지지 않는다.
- 작은 타일 내부 글자는 보조 정보로 취급한다. 선택 시 고정 크기 상세 패널에서 이름·효과·배치 가능 여부를 확인할 수 있게 한다. 터치도 호버 없이 상세에 접근할 수 있어야 한다.
- 선택 강조는 외곽선과 아이콘을 병행하고, 색상만으로 선택·소유자·배치 가능 상태를 구분하지 않는다. SVG 외곽선은 배율에 영향을 받지 않게 유지한다.
- 타일과 확대 제어는 키보드로 조작 가능하게 하고, 접근 가능한 한국어 이름·현재값·선택 상태를 제공한다.
- 보드 확대·이동 이후에도 화면 좌표를 SVG 좌표로 정확히 변환하여 의도한 육각형이 선택되게 한다.
- 버튼은 충분한 터치 영역을 제공하며, 확대 시 보드나 고정 패널이 필수 제어를 가리지 않게 한다.
- 브라우저 자체 확대, 작은 화면, 동작 감소 설정도 고려한다.

## 7. v0.2.1 규칙 엔진과의 경계

- 이번 문서는 표시 계층의 요구사항만 정의한다. 기존 규칙 엔진 설계·타일 효과·득점·차례·데이터 구조를 변경하지 않는다.
- 다음 UI 구현에서는 엔진 상태를 읽는 보드 어댑터와 보기 설정 상태를 분리한다. 확대·이동 이벤트를 게임 행동으로 전달하지 않는다.
- 타일 배치 등 실제 행동의 합법성은 엔진의 판단 결과를 표시한다. UI에서 별도의 임의 규칙을 만들지 않는다.
- 데모와 공식 규칙의 구분을 유지한다. 보기용 방패·교역로 표시를 정식 확장 규칙 구현으로 간주하지 않는다.
- 설정 복원·레이아웃 전환이 게임 초기화나 엔진 상태 재생성을 유발해서는 안 된다.

## 8. 다음 구현 단계의 완료 기준

1. 두 모드 각각에서 2·3·4인 게임의 공용 보드와 모든 영지가 같은 페이지에 존재하고 스크롤로 접근 가능하다.
2. 내 보드 중심 모드에서 내 영지는 상단, 상대 영지는 아래쪽에 유지되며 차례 전환으로 교체되지 않는다.
3. 전체 및 개별 배율을 50~200%에서 1% 단위로 지정할 수 있고, 휠·버튼·숫자/슬라이더 제어가 같은 상태를 반영한다.
4. 타일 선택 후 확대·축소·드래그·모드 전환에도 선택이 유지되고, 드래그 종료가 배치로 처리되지 않는다.
5. 각 보드의 네 모서리까지 이동·스크롤로 접근 가능하며, 맞추기와 초기화로 쉽게 복귀한다.
