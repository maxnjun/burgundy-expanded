## 추출 규격

- 7장 모두 768×768 RGBA PNG. 실제 그림의 최대 길이 744px, 가운데 배치, 최소 12px 투명 여백. 연결된 바깥 크림색만 제거하고 타일 내부 그림·금색 테두리·눈금은 유지했다.
- 원본 앞면 외곽은 378×347 / 370×347 / 378×347 / 378×346 / 370×346 / 378×346px, 뒷면은 512×512px다. **원본 앞면 자체가 완전한 정사각형이 아니므로**, 왜곡·잘림 없이 단일 등방 배율로 정사각형 캔버스에 넣었다. 따라서 앞면의 위아래 투명 여백은 35~43px로, 정사각형 뒷면의 12px와 다르다. 프레임 폭·캔버스·중심은 같으며 원본 종횡비 차이는 보존한다. 이를 숨기기 위한 늘이기나 테두리 재제작은 하지 않았다.
- `scripts/prepare-goods-assets.py --check`: 원본 해시, 인쇄된 검은 눈금 연결요소 1~6개, 전체 픽셀 재현, 매핑·해상도·알파 검사. `pipBounds`는 실제 PNG 안의 인쇄 눈금 영역이며, 공급처 주사위와의 겹침 검증에 사용한다.
- `scripts/validate-deployment-assets.py`: 배포 파일 7장의 해시·RGBA·해상도·알파 경계를 추가 검증. CI에서도 추출 재현 검사를 실행한다.

## 적용 구조

`src/app/tile-art.tsx`의 기존 `GoodsArt` / `GoodsBackArt`만 교체했다. SVG viewBox(40 / 30), 크기 props, 좌표·클릭 대상은 그대로다. 파일 해시 쿼리로 캐시를 갱신한다. 승인 그림에 테두리와 주사위가 있으므로 정상 로드 시 기존 SVG 그림·주사위를 중복 표시하지 않는다. 로드 실패 때만 기존 SVG로 복구한다.

기존 호출부인 공용보드 라운드 상품·공급처(`CommonBoard`, `GoodsSpace`), 로컬/온라인 개인 보관함·판매 내역(`GoodsInventory`, `SoldGoods`), 방패 상품 선택(`RewardArt`), 무역로(`TradeRoutePanel`), 도움말(`TileHelpContent`)에 공통 적용된다. 모든 뒷면은 값이 없는 단일 파일·동일 URL이다. Design 1과 무관하게 같은 그림을 사용한다.

페이즈 시작 시 상품 5개 공개, 공급 완료 위치 빈칸, 상품 종류·수량·획득·판매·점수·서버 검증·저장 구조는 변경하지 않았다. 현재 게임에서 공개하는 상품을 임의로 뒷면으로 가리지 않는다.

## 검증 및 증거

최종 실행 결과는 `docs/PROGRESS.md` 상단에 기록한다. `.local-data/goods-assets/`에 변경 전후 PC·모바일 캡처, 7종 비교·두 디자인·3배율, 획득·판매·Undo·온라인 동기화·재접속 검증 로그를 보관한다. `_preview_sheet.png`는 7장 전체를 흰색/어두운 바탕 위에 보여 준다.

원본에 없는 정보를 복원하거나 그림을 다시 그리지 않았다. 실제 Android/iPhone 기기와 운영 Redis에서의 게임은 이번 검사 범위 밖이다. Render에는 배포하지 않는다.
