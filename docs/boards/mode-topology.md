# 팀·솔로 보드 연결 구조와 전사 재개

현재는 보드 데이터 검증 기반만 구현했다. 공식 솔로/팀 게임의 실행 모드가 아니다. 전체 TODO의 T61 완료, T62b 및 T63~T67b 미완료와 연결된다.

## 구현 경계

`src/game/boards/mode-topology.ts`의 `ModeBoardDefinition`은 기존 셀·지역·시작 성·출처 검증 계약을 재사용한다. 개별 기본판의 `validateBoardDefinition`은 변경하지 않는다. 다음 두 개념을 구별한다.

- `regions`: 같은 색의 최대 연결 성분. 기존 지역 완성 점수의 단위다.
- `areas`: 육지/섬 구역의 완전한 셀 분할. 서로 다른 색 지역을 포함할 수 있다. 각 구역은 물리적으로 연결되어야 한다.

솔로 접촉은 같은 육지 구역의 axial 인접 또는 명시된 `riverLinks`를 사용한다. 팀 접촉은 기본 axial 인접이다. 강 연결은 양방향이고 자기 연결·중복·없는 칸·같은 육지 구역 연결을 거절한다. 거리순/가까운 파란 칸/같은 색을 기준으로 강을 자동 생성하지 않는다.

`modePlacementFrontier`는 점유 칸에서 한 단계 닿는 빈 칸 후보만 반환한다. 빈 칸을 경유해 연쇄 도달하지 않는다. 주사위·타일 지형·건물 중복·효과·모드별 제한을 검증한 **합법 GameAction이 아니다**. 실제 모드 어댑터의 별도 검증이 필요하다. `modeBoardNeighbors`는 검증된 typed 정의를 대상으로 사용한다. 외부 JSON 파서로 쓰지 않는다.

기존 BoardRegionDefinition의 정합성/시작 성/출처 근거를 유지한다. 구조 검증 성공이 원본 일치나 공식 인증을 뜻하지 않는다. 테스트의 작은 섬은 TEST FIXTURE이며 카탈로그/UI에 등록하지 않았다.

## 솔로 사진 전사 초안

`src/game/boards/drafts/solo-33.ts`는 공식 PDF p.15 원본 포함 이미지 Im3.jpg(923×693)에서 읽은37칸이다. 사진 번호는 보이지 않으며, 준비 문맥의 초보자33번은 후보 식별이다. 실제 사진의 면 식별도 검수해야 한다.

| 육지 구역 | 위에서 아래 각 행 칸 수 | 합계 |
| --- | --- | --- |
| 북서 | 2, 3, 2 | 7 |
| 북동 | 4, 4, 3 | 11 |
| 남서 | 2, 2, 2 | 6 |
| 남동 | 4, 5, 4 | 13 |

각 섬은 자체 원점에서 시작하는 local axial 좌표다. 전역 좌표가 아니므로 네 배열을 단순 합쳐 ModeBoardDefinition으로 사용하면 안 된다. 실제 지형/숫자를 추가 생성하지 않고 전역 이동 변환과 강의 칸별 접점을 따로 검수해야 한다. 구조 검사3개는 사진의 독립 대조를 대신하지 않는다. 현재 초안은 선택 불가능하다.

## 다음 작업

1. 원본 사진과 TS 행별37칸을 독립적으로 다시 대조하고, 숫자가 불명확한 칸은 미확정으로 남긴다.
2. SE33 면 식별과 강 연결의 칸별 의미를 공식 근거로 확인한다. 단순히 ‘다른 지역은 강을 통해서만’이라는 문장만으로 접점을 추정하지 않는다.
3. 지형/숫자를 바꾸지 않는 섬별 axial 이동 변환 및 렌더 위치를 검수한다. 강 밖의 인위적 접촉을 만들지 않는다.
4. 검수된 정의를 주입하고 T61 검증·강 경유 후보·시작 성별 도달 검사를 작성한다. 이후 별도 솔로 엔진/UI에 연결한다.
5. 팀 보드는 p.15 사진부터 별도로 전사한다. 현재 기본판 영지1~30을 팀/솔로 공식 보드로 재사용 표시하지 않는다.

공식 p.16의 점수/종료 계산은 `src/game/modes/solo-scoring.ts`에 분리했다. 하나의 순서가 정해진 득점 이벤트만 계산하며 추가 행동의 발생 여부를 반환한다. GameAction 큐, 여러 부분 득점의 순서 선택, 실제 추가 행동, 수도원 즉시 점수·색 완성·검은 무효과 타일·라운드 공급은 후속 모드 어댑터 작업이다.
